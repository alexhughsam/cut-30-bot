# CLAUDE.md — working in this repo

## Read the repo BEFORE answering anything (non-negotiable)
This repo IS the source of the coaching philosophy. Before coaching, gut-checking a hook,
or answering any question, read these files first and treat them as primary — they
override outside research and memory:

1. **`PROMPT.md`** — the Cut30 Coach operating manual. The written hook/script philosophy
   lives here, not just in web research:
   - **North star** (top): "a video worth stopping for, said in fewer words than feels
     comfortable, with a reason to watch it twice."
   - **"The bar for 'done'" → "For a script"** — the concrete, checkable definition of a
     good hook (first line opens a loop/stake/tension + a storyboard-able first frame;
     every remaining word does stop-scroll or rewatch work; a nameable reason to rewatch).
     **Quote and grade against this bar directly** when answering a hook question.
   - **House rules** — ground claims in Cut30 (`[DOCUMENTED]`/`[MY READ]`), reason don't
     template, everything serves hook/retention/one message, be dense, primary sources win.
   - **Who grades it** — the reviewer loop: whatever wrote a thing doesn't grade it; spin
     up a fresh sub-agent to break it, cap 5 passes.
2. **`CUT30_PLAYBOOK.md`** — documented vs unverified Oren John doctrine (with sources).
   **ALWAYS refer to this playbook** on every hook/script/coaching answer — read it and
   pull the relevant `[DOCUMENTED]` principle each time; never answer without consulting
   it. It supplements `PROMPT.md` (which stays primary if the two ever conflict), and keep
   it current — fold new confirmed findings back into it as they come up.
3. **`PROFILE.md`** — the creator's standing profile. Don't re-ask what's here.
4. **`SWIPE_FILE.md`** — hooks that survived the loop. Build on these, don't start cold.

Rule of thumb: if the repo already states the philosophy (it does, in `PROMPT.md`), answer
FROM it first, then supplement with research — never the other way around.
